# Port from Go to Rust

## Decision

layerlock moves from Go to Rust. The behaviour, flags and exit codes stay the same. Release assets get
new names.

## Why

- **AI-assisted maintenance.** layerlock is mostly maintained with AI coding tools, and they work better
  against the Rust compiler's detailed errors than against Go.
- **One build setup.** printerkeep already builds static Rust binaries for every Pi target with rust-lld and
  Rust's bundled musl: no zig, `cross` or C cross toolchain. layerlock uses the same setup
  (`.cargo/config.toml`, `flake.nix`, `rust-toolchain.toml`, release workflow).
- **Smaller and faster**, though this alone wouldn't have justified a rewrite (see below).

## Benchmark

Both versions run against a local fake Moonraker on x86_64; 2,000 interleaved runs after 50 warm-up runs.
Peak memory measured with GNU `time`. Go built as GoReleaser did (`CGO_ENABLED=0`, `-s -w`); Rust with the
release profile in `Cargo.toml` (`opt-level = "z"`, LTO, static musl).

|                       | Go 1.26 | Rust (musl, static) |
| --------------------- | ------- | ------------------- |
| Time per run, median  | 2.9 ms  | 1.2 ms              |
| CPU time per run      | 3.4 ms  | 1.1 ms              |
| Peak memory           | 6.4 MB  | 0.8 MB              |
| Binary, x86_64        | 6.2 MB  | 0.76 MB             |
| Binary, arm64         | 5.8 MB  | 0.68 MB             |
| Binary, armv7         | 6.0 MB  | 0.63 MB             |
| Binary, armv6         | —       | 0.68 MB             |

An earlier build with `ureq` 2 ran in 0.8 ms per check. `ureq` 3 costs about 0.5 ms more, but `ureq` 2 only
gets maintenance fixes, so layerlock uses 3.

For a check that runs once before a job, the time difference doesn't matter; the memory and size gains are
nice on a Pi but small in absolute terms.

## Trade-offs

- **Dependencies.** Go used only the standard library. Rust uses `ureq` (HTTP, no TLS) and `serde`: 63
  crates in `Cargo.lock`, most of them pulled in by `ureq`. A hand-written HTTP/1.1 GET would cut
  that to a few crates if it ever matters.
- **Build time.** A clean release build takes about 15 s instead of about 1 s.

## Compatibility

- Flags parse like Go's `flag` package: `-url` and `--url`, `--url=<value>`, and Go duration strings for
  `--timeout` (`500ms`, `1m30s`), so existing unit files keep working.
- Changes in behaviour:
  - A usage error (unknown flag, bad value) exits 255, not 2. Go's `flag` package exited 2, which is also the
    "paused" code, so a typo in a unit file looked like a paused print and skipped the unit forever.
  - New `--help`/`-h` (stdout, exit 0) and `--version`.
  - The client never uses an HTTP proxy from the environment: Moonraker is on the local network. (Go's
    client used `HTTP_PROXY` for non-localhost URLs.)
  - A trailing `/` in `--url` is ignored.
- Release assets are renamed to match printerkeep: `layerlock-linux-{aarch64,armv7,armv6,x86_64}` and
  `layerlock-checksums.txt` (were `layerlock_linux_{arm64,armv7,amd64}` and `layerlock_checksums.txt`).
  `install.sh` falls back to the old names, so it still installs v1.0.0 and older. An `install.sh` from
  v1.0.0 or older can't install the new releases.
- New armv6 build for the Pi Zero and Pi 1. `install.sh` used to install the armv7 build there.
